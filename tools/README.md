# Operator tools

Commands run over SSH on the server. **None of them is reachable from the
internet, and none should become so.**

That is the design, not an oversight. Deleting accounts, reassigning
ownership and removing trips all need a privileged role to guard them if
they are routes, and that role's login then becomes the most valuable
credential in the system — a worse problem than the leftover account or
dead folder it would tidy up. Whoever can reach the auth directory over
SSH can already do all of this by hand. These just do the arithmetic, and
refuse the mistakes.

All of them are **Node 10.24.1 compatible**, because that is what the
production host runs. All of them **preview by default** and write
nothing without `--confirm`. All of them **back up the auth directory**
before touching it.

## Running them

`node` is not on the interactive shell's PATH — it lives in the cPanel
Node virtualenv:

```bash
source ~/nodevenv/TOS/10/bin/activate && cd ~/TOS
```

Everything below assumes that has been done.

---

## `trips.js` — what is on this server

```bash
node tools/trips.js
node tools/trips.js remove <folder>            # previews
node tools/trips.js remove <folder> --confirm
node tools/trips.js restore <folder> --confirm
```

Lists every trip with its owner, who else can open it, day count, how
much journal is in it, size and when it was last touched. Surfaces two
states nothing in the app can show you: a trip with **no ownership
record** (invisible — nobody can open it), and an ownership record whose
**folder is gone** (harmless, but it explains a trip shared with you that
is not there).

**`remove` moves, it does not delete.** The folder goes to
`data/projects-removed/` with a timestamp. Photos and notes are the part
nobody can write again, so it says what is in a trip before it touches
it. When you are certain, `rm -rf` the archived folder yourself.

## `adopt-trip.js` — give a trip folder an owner

```bash
node tools/adopt-trip.js <folder> <username> --share <username>:write --confirm
```

A trip that arrives any way other than through the app — restored from a
backup, copied over SSH, generated by `make-test-trip.js` — has no
ownership record, so `getTripPermission` returns null for everybody. The
folder is on disk, the data is intact, and **nobody can open it**, with
nothing saying why. `claimUnownedTrips()` only runs for the first user
ever registered, so it is no help afterwards.

## `make-test-trip.js` — a test copy, moved to now

```bash
node tools/make-test-trip.js <source-folder> --days 10 --today 5 --confirm
```

Takes the first N days of a real trip, shifts the dates so today is day
N, adds a drive on every day that changes where you sleep, and invents
photo locations and breadcrumbs for the days already past. Fuel prices,
toll types and the breadcrumb answer are filled in so the thing being
tested is visible without any setting up.

It exists as a script rather than a committed folder because
`data/projects/` is gitignored — this repo is public and a pull must
never collide with live trip data. Building it here also means it reads
the *real* trip rather than a copy.

The generated trip has no owner; run `adopt-trip.js` next.

## `remove-user.js` — remove an account

```bash
node tools/remove-user.js <username> --give-trips-to <username> --confirm
```

Transfers owned trips to a named heir, withdraws collaborator entries and
drops live sessions so removal is immediate. Refuses to orphan a trip —
a trip whose owner does not exist has nobody who can share, rename or
delete it — and refuses to remove the last account, which would flip the
app into first-run mode and let the next visitor claim everything.

## `build-airports.js` — regenerate the airport list

Rebuilds `assets/data/airports.json` from the upstream source. The
`SUPPLEMENT` list is seeded first so airports added by hand (WSI, for
one) survive a rebuild rather than being overwritten by upstream.
